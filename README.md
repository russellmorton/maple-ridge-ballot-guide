# Maple Ridge Ballot Guide

Independent, non-partisan guides to two elections a week apart:

- **Municipal, October 17, 2026** (`/municipal`): every declared candidate for mayor, council and SD42 school trustee, the three recreation borrowing questions, and issue-by-issue comparisons.
- **Provincial, October 24, 2026** (`/provincial`): find your riding from your address, every candidate in Maple Ridge's two ridings and the ridings next door, and what each party is promising.

Every position links to its source. Not affiliated with the City of Maple Ridge, School District 42, Elections BC, the Government of B.C., any party, candidate or elector organization.

## Structure

Static site, no build step.

| File | What it holds |
| --- | --- |
| `index.html`, `landing.js` | Landing page: one card per election, next one first, and a "what's different" table. Also forwards old links (`/#candidates`, `/#c-ruimy`) to `/municipal`. |
| `guide.css` | Shared layout and styles (light and dark themes). Each guide sets its own palette. |
| `theme.js`, `chat.js` | Theme toggle and the "Ask the guide" panel, shared by both guides |
| `municipal/data.js` | **All municipal content**: candidates, positions, sources, ballot questions, voting info |
| `municipal/app.js` | Municipal rendering, filters, comparison grid, "My ballot" |
| `provincial/data.js` | **All provincial content**: ridings, candidates, parties and platforms, voting info, sources |
| `provincial/app.js` | Provincial rendering: riding finder, ridings, candidates, parties, compare, "My vote plan" |
| `provincial/map.js`, `lib/districts.js` | Riding boundaries, generated by `scripts/fetch-districts.mjs` |
| `api/chat.js`, `lib/guides/` | "Ask the guide": one prompt per guide, built from that guide's `data.js` |
| `api/riding.js`, `lib/riding-lookup.js` | Address → riding, via the BC Address Geocoder and DataBC boundaries |
| `api/feedback.js` | Feedback form (records which guide it came from) |
| `vercel.json` | Clean URLs, function settings and security headers |

Saved choices ("My ballot", "My vote plan") stay in the visitor's browser. The riding finder never stores the address.

## Editing content

Everything voters read lives in each guide's `data.js`. To correct a candidate's position, edit their `positions` entry:

```js
housing: { stance: "priority", text: "What they said…", source: "mrnDebate" },
```

- `stance` is one of `supports`, `opposes`, `mixed`, `priority`, `none`.
- `source` must be a key in `sources`. If there's no source, use `stance: "none"` and leave out `text`.
- When a candidate sends their position directly, quote it word for word with `source: "candidate"` (shown as "Sent to us by the candidate", with no link).
- Provincial party platforms use `points` (a list of short commitments) per issue, with one `source`.
- Update `lastChecked` at the top of the file when you re-verify, and add a `changes` entry for every correction.

`npm test` checks that every source, riding, party and stance in both data files resolves.

## Riding boundaries

The address lookup and the riding map use DataBC's *Current Provincial Electoral Districts of British Columbia*. After changing the ridings in `provincial/data.js`, regenerate both files:

```sh
node scripts/fetch-districts.mjs
```

Without them the lookup still works, by asking DataBC's district layer live. Elections BC says boundary files shouldn't be the final word on a voter's riding, so the site always links to Elections BC's own lookup.

## Run locally

```sh
npm ci

npx serve .
```

## Deploy

Live at **https://vote-maple-ridge.vercel.app**. The Vercel project is connected to this repo:

- Every pull request gets its own preview deployment (linked on the PR).
- Merging into `main` deploys to production. `main` only accepts changes through pull requests.

Optional environment variable: `GEOCODER_API_KEY` for the BC Address Geocoder (it works without a key at low volume).
